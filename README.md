# grafana-config-sync

Keep a live Grafana's config in git, including the parts Git Sync doesn't cover.

Grafana 12's **Git Sync** handles dashboards and their folders, and nothing else. Alert
rules, the notification policy tree, contact points, mute timings and templates aren't
covered. These scripts fill that gap. They also handle the Git Sync cutover itself and a
full read-only snapshot of the instance.

Tested against Grafana **12.4.2**.

## Quick start

```sh
cp .env.example .env              # GRAFANA_URL + admin creds or a service-account token
uv sync
uv run scripts/grafana-sync.py status   # compare repo vs live; writes nothing
uv run scripts/grafana-sync.py push     # provisioning/alerting/ -> Grafana
uv run scripts/grafana-sync.py pull     # Grafana -> alerting/ (generated snapshot)
uv run pytest                           # offline tests, no Grafana needed
```

## Layout

| Path | Direction | What |
|---|---|---|
| `provisioning/alerting/` | **source → Grafana** | Rule files (`rules-*.yml`) and the policy tree. These use Grafana's own file-provisioning format, so a dev docker stack can bind-mount the same files. |
| `alerting/` | **Grafana → here** | Generated by `pull`. It's the only record of rules that were created in the UI. **Exported decrypted, so keep it in a private repo** (it's gitignored here). |
| `instance/`, `dashboards/` | **Grafana → here** | Generated by `grafana-backup.sh`. Holds folders, datasources, permissions, settings, and dashboards in the exact bytes Git Sync writes. |

## Scripts

| Script | What it does |
|---|---|
| `grafana-sync.py {status,push,pull}` | The one entry point for alerting. |
| `grafana_push_alert_rules.py` | Pushes rule files over the provisioning API. It's additive: the `DELETE` verb is refused outright, an existing rule is only changed with `--update`, and an unchanged rule is a no-op. |
| `grafana_push_notification_policy.py` | Converges the policy tree. It inserts missing routes in the right order and fixes their timings. It never removes or reorders a route, and it backs up the tree before the single PUT. |
| `grafana_pause_alert_rules.py` | Retires a rule by pausing it instead of deleting it. The rule is backed up first and can be unpaused later. |
| `grafana-backup.sh` | Read-only snapshot of the whole instance (only GETs). It builds in a staging dir and swaps it in only after every fetch succeeds. |
| `grafana-canonicalize-dashboards.py` | Rewrites dashboards into Git Sync's exact bytes. Without this, the first UI save of each dashboard rewrites the whole file instead of producing a one-line diff. |
| `grafana-gitsync-connect.py` | Creates or repairs the Git Sync `Repository`, plus its `Connection` when you use a GitHub App. It's idempotent, and `--check` only reports. |
| `grafana-check-folder-permissions.py` | Compares live permissions against the snapshot, matching folders by **title** (Git Sync gives folders new uids). |
| `grafana-restore.sh` | Loads datasources, folders and dashboards into another instance. |

## Traps these scripts handle

Each of these broke something in production at least once. All of them fail **silently**.

**Alerting API**
- **A contact point's `url` never comes back.** Every read endpoint returns `[REDACTED]`, so
  a PUT built from a GET overwrites the live webhook with that literal string. The real
  value is only available from `.../contact-points/export?decrypt=true` with an **admin**
  login. That's why `push` never writes contact points.
- **Grafana respells durations.** `24h` comes back as `1d` and `0m` as `0s`. If you compare
  the strings, every run reports a change. Compare seconds instead.
- **Fields left out of the payload are dropped without an error.** The push still reports
  `created`. `keep_firing_for` was lost this way.
- **Provenance.** Rules want `X-Disable-Provenance: true` so they stay editable in the UI.
  A policy tree that's already provenance `api` gets a 403 if you send that header.
- **Retried POSTs.** If the link drops the response to a POST that actually landed, the
  retry gets a 409. The pusher reads the rule back and decides by its content.
- **Folders are resolved by title.** A title that isn't unique is refused instead of
  first-match-wins. A folder that's missing gets created, so a typo in a rule file makes a
  new folder.
- **Never delete a folder because it looks empty.** `/api/search` only counts dashboards,
  so folders that hold every alert rule show zero children.

**Notification routing**
- **Route order matters.** Routing is first-match-wins (`continue: false`), so a narrow
  route placed after a broad one is never reached. The policy pusher refuses to write a
  tree in the wrong order.
- **The policy tree doesn't show everything.** A rule with
  `notification_settings.receiver` bypasses the tree entirely, so audits must read the
  rules too.

**Git Sync**
- **Turning on Git Sync for an instance that already has data** needs
  `enableMigration = true` under both `[unified_storage.folders.folder.grafana.app]` and
  `[unified_storage.dashboards.dashboard.grafana.app]`. Without it, Grafana won't start.
  A fresh test instance won't catch this.
- **The GitHub App must declare `repository_hooks: write`**, even if no webhook ever
  arrives. Grafana checks the App's declared permissions unconditionally.
- **Git Sync applies commits but doesn't fix drift.** An old classic file provider in
  `/etc/grafana/provisioning/dashboards/` silently reverts dashboards on every restart.
- **git→Grafana sync can stall** while health still reads fine. The tell is
  `status.sync.finished` going stale; POSTing a `pull` job clears it.

## CI

The tests run offline. CI can't reach your Grafana, so a green check says nothing about
whether the live instance matches the repo. Only `status` does.
